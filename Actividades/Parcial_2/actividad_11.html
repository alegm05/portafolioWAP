Actividad 11: Lab: File path traversal, validation of start of path

Laboratorio de evaluación ofensiva enfocado en la evasión de validaciones de prefijo estricto, empleando la concatenación de la ruta base requerida con secuencias relativas de escape de directorio.

NIVEL / TIPO

Dificultad: Practitioner
Vulnerabilidad: CWE-22 (Improper Limitation of a Pathname to a Restricted Directory)

OBJETIVO TÉCNICO

La aplicación valida que la ruta suministrada comience estrictamente con la carpeta esperada. El objetivo es evadir esta validación manteniendo el prefijo obligatorio e inyectando secuencias de escape (../) a continuación para extraer /etc/passwd.

[THEORY_02]

Marco Teórico

Fundamentación de la Vulnerabilidad

Esta variante de Path Traversal (OWASP A01:2021 - Broken Access Control) explota un control de seguridad incompleto. En lugar de verificar si el archivo final reside dentro de un directorio seguro, la aplicación se limita a inspeccionar cómo comienza la cadena de texto suministrada por el usuario.

Mecánica de la Validación de Inicio de Ruta

En el código backend (ej. usando startsWith() en Java), el desarrollador implementa una verificación para asegurar que la entrada comience con una ruta autorizada (como /var/www/images/). Si la condición se cumple, asume erróneamente que toda la cadena es segura.

El Fallo en la Lógica de Prefijos

El mecanismo falla porque el sistema operativo procesa las secuencias relativas (../) independientemente de lo larga o restrictiva que sea la ruta inicial. Si la cadena empieza validamente, el filtro la deja pasar, pero el sistema operativo resolverá los ../ subiendo niveles jerárquicos hasta alcanzar el archivo objetivo.

[EXEC_03]

Procedimiento

Fase 1: Interceptación e Identificación del Parámetro

Tras configurar Burp Suite e inspeccionar el tráfico de carga de imágenes, se identificó que la aplicación expone la ruta absoluta completa en el parámetro GET: filename=/var/www/images/45.jpg.

>_ Evidencia: Historial de Burp Suite mostrando la solicitud GET con el parámetro revelando la ruta absoluta del servidor, y su derivación a Repeater.

Fase 2: Construcción del Payload Híbrido

Dentro del módulo Repeater, para satisfacer la validación del backend y a la vez explotar la vulnerabilidad, se construyó un payload híbrido. Se mantuvo intacto el prefijo obligatorio (/var/www/images/) y se concatenaron inmediatamente las secuencias de escape de directorio.

>_ Evidencia: Ataque exitoso en Repeater mostrando el payload con prefijo validado (izquierda) y el volcado de usuarios de Linux (derecha).

Fase 3: Verificación de Compromiso

El filtro permitió el paso de la cadena al iniciar correctamente, mientras que el sistema de archivos resolvió la navegación relativa, devolviendo el contenido de `/etc/passwd`. La plataforma validó la exfiltración exitosa.

>_ Evidencia: Confirmación visual del estado "Lab Solved", validando la resolución técnica del reto.

[PAYLOAD_04]

Análisis Téc.

Mecánica del Payload de Evasión

HTTP Request - Start of Path Bypass
GET /image?filename=/var/www/images/../../../etc/passwd HTTP/2
Host: 0a79003504fb7a...web-security-academy.net
Accept: image/webp, image/apng, image/*
Sec-Fetch-Site: same-origin
  • Satisfacción del Filtro: El código del servidor inspecciona la cadena recibida para asegurarse de que empiece con /var/www/images/. Como el payload cumple esta condición, la validación de seguridad devuelve True.
  • Evasión Estructural: La API del SO recibe la cadena completa. Se ubica en /var/www/images/, y luego los tres ../ la obligan a retroceder hasta la raíz /, para finalmente descender a etc/passwd.

Defensa en Profundidad y Remediación

1. Validación Estricta Post-Canonicalización

Validar prefijos utilizando funciones como startsWith es inútil contra Path Traversal. La defensa debe aplicarse después de canonicalizar la ruta (ej. File.getCanonicalPath()). Una vez resuelta la ruta real, entonces se verifica que el directorio resultante esté confinado dentro de la carpeta base permitida.

2. Eliminación de Referencias Absolutas en el Frontend

La aplicación nunca debe exponer rutas completas del sistema operativo (como /var/www/images/) en los parámetros HTTP del cliente. Esto causa Information Disclosure y facilita la estructuración de ataques. Se deben utilizar identificadores opacos.

3. Principio de Menor Privilegio (Sandboxing)

El proceso del servidor web (www-data) no debería tener permisos de lectura en /etc/. Se deben implementar mecanismos de enjaulamiento (chroot jails o AppArmor), obligando al proceso a considerar la carpeta de la aplicación como el límite superior inquebrantable.
